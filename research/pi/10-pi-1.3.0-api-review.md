# Pi 1.3.0 — adapter API verification

Reviewed **2026-10-19**, before adapter implementation. Companion:
[execution-path coverage and no-fork conditions](11-pi-1.3.0-execution-coverage.md).
This is a release-specific review, not a claim about moving `main` or a
production conformance certificate. No Loom dependency or runtime pin changed.

- Official Git tag `v1.3.0` resolves to
  [`71023aec1546d6d677a65669c5665c0927ce0dd0`][release]. Source was downloaded
  at that commit, not at the later main commit in the October 16 drift note.
- Published [`@earendil-works/pi-coding-agent@1.3.0`][npm] was downloaded and

  `1.4.3`: create session, prompt, subscribe, read stats and entries, abort,

## Contract changes and pitfalls the adapter must account for

1. **`before_agent_start` is a discriminated union.** Since 1.2.0,
   idle runs started by `pi.sendMessage(..., { triggerTurn: true })` also
   emit it. Read `event.prompt` only when `event.messageType === "user"`;
   custom-start events carry `message`. Busy/abort behavior during startup
   changed too. [Release notes, lines 57–63][changes], [types][types].
2. **Do not mistake `tools: ["read", "codemode"]` for an MCP denylist.**
   Ordinary allowlists can leave MCP tools registered for codemode/search.
   An empty list disables them; entries starting `mcp__` narrow the MCP set,
   and `excludeTools` applies too. Use explicit inventory and per-call
   authorization, not only model-visible selection. The 1.3.0 resume fix
   also restores tools activated earlier unless explicit selection overrides
   them. [SDK, lines 64–92][sdk], [changes, lines 25–28][changes].
3. **Meter more than agent turns.** `getSessionStats()` sums dedicated usage,
   compaction/branch-summary usage, tool-result usage, and assistant usage
   across entries, not just the active branch. Do not double-count them.
   Cache warming can issue provider requests outside ordinary tool calls;
   its default mode is `streaming`. Disable it initially
   (`cacheWarming: "off"`) until its spend/kill/metering path is covered;
   a failing `cache_warming_decision` handler falls back to Pi's decision,
   not fail-closed. [Stats][stats], [defaults][defaults], [warmer][warmer].
4. **Provider timeouts/retries are not a whole-run deadline.** Classifier
   timeout is fresh per attempt; the outer caller signal must bound retries
   and backoff too. Maintain the Loom deadline and attempt budget outside
   the DB transaction. [Classifier transport][classifier-transport].
5. **Some older experimental references are obsolete.** The 1.2.0 changelog
   removes the source-only experimental server/client/plugin stack. Do not
   implement against old `src/experimental` references in the October 1
   research. The public SDK above is independent of that stack.
   [Changes, lines 107–110][changes].

## System One: old limitations still reproduced

The public registry/runtime/classifier chain remains usable, but it does
not supply Loom's semantic validation. [Registry][registry],
[runtime classify][runtime-classify], [System One parser][parser].

The offline probe supplies deliberately invalid mock provider output and
asserts the actual normalized result:

- Choice selecting an unknown option, mismatched probability keys,
  probabilities `-1` and `3`, confidence `9`, and bool probability `2`
  are accepted with `stopReason: "stop"`. Numeric finiteness is checked;
  range, membership, exact key set, sum and argmax consistency are not.
- Score level distribution/legend are still discarded.
- A response's versioned server model ID is not preserved: result uses the
  requested `jev-latest` alias.
- Negative usage becomes zero; missing usage may be omitted.
- Without `timeoutMs` or caller signal, the mocked fetch receives no abort
  signal. An explicit timeout resolves to `stopReason: "error"`; caller
  abort resolves to `"aborted"`. Registry/runtime failures also resolve as
  result objects rather than reliably rejecting.
- Mocked `503` responses retry twice by default (three total attempts),
  with a distinct timeout signal for each attempt; the probe verifies both.
- A pre-aborted caller signal is forwarded to the fetch implementation,
  but the helper still invokes that fetch once. Native fetch honors the
  signal; a custom transport must do so too. Loom should check its deadline/
  kill state before dispatch, not infer non-execution from the final
  `"aborted"` label. [Transport][classifier-transport], [retry loop][retry].
- The **published offline TypeSafe catalogue contains only `jev-latest`**;
  `findOfType("classifier", "typesafe", "jev-1.13.0")` returns undefined.
  Its baked input price is **zero**, not evidence that inference is free.
  A versioned model and pricing need explicit configuration/verification
  before a calibrated or cost-controlled experiment. Remote catalogue
  refresh may differ; it was disabled for this check.
  [Published catalogue][catalogue].

Thus the R-36 recommendations survive: Loom validates outputs, records
resolved versions when available, meters every attempt independently,
and keeps classifiers advisory. R-35 model-quality validation remains open.

## Reproduce the offline API proof

The assert-based probe is [probes/1.3.0-api.mjs](probes/1.3.0-api.mjs).
Install only into a disposable external directory; no Loom dependency is
required. From the Loom repository root:

```bash
mkdir -p /tmp/opencode/loom-pi-api-check
npm install --prefix /tmp/opencode/loom-pi-api-check --ignore-scripts --no-audit --no-fund --save-exact @earendil-works/pi-coding-agent@1.3.0
cp research/pi/probes/1.3.0-api.mjs /tmp/opencode/loom-pi-api-check/
node /tmp/opencode/loom-pi-api-check/1.3.0-api.mjs
bun /tmp/opencode/loom-pi-api-check/1.3.0-api.mjs
```

Observed: all three PASS groups under both runtimes, plus five consecutive
repeat runs per runtime after explicitly awaiting model-runtime refresh.
The fixture sets
`PI_OFFLINE=1`, uses an in-memory credential store and a faux provider,
blocks unexpected global fetch, and uses a fake fetch for classifier
responses. Test session files live only under `/tmp/opencode`. Installation
itself uses npm/network; the probe makes no real model/API calls.
Transitive dependency resolutions are not a production lockfile.
Loom's existing three tests and `bun run check` also pass. The initial full
lint failed on pre-existing, git-ignored `.obsidian/` files because Biome's
VCS ignore integration was disabled. The follow-up enables Git ignore
support in `biome.json`; the full lint now passes without changing any
Obsidian files.

## Remaining proof before promotion

- No real provider, real MCP server/OAuth handshake, production sandbox,
  cross-process lease/effect fencing or kill-race drill was executed here.
- Availability checks alone cannot certify safety. The adapter still needs
  a deny-by-default execution corpus, bounded verification attempts,
  startup-hook readiness checks and OS/effect-boundary enforcement, as
  specified by the companion note. Neither report authorizes a re-pin or
  claims T-08–T-11 implemented.
