## Findings

### R-001 — Malformed cursor can be silently repaired before validation

- **Severity:** Medium — bounded persisted-state validation defect.
- **Artifact/file:** fixed T-04 overlay, `src/store.ts:1331–1340,1374–1407,1439`; incomplete regression at `tests/outbox.test.ts:718–741`.
- **Confirmed observation:** cursor validation runs only when constructing the final relay return value. Dispatch admission first updates the existing cursor using `max(last_id, excluded.last_id)`. Consequently, a negative persisted cursor can become a valid positive ID before `relayCursor` examines it.
- **Triggering scenario:** start with valid pending scoped work; add the unrelated negative-ID outbox row used by the existing malformed-cursor fixture, using distinct intent/action UUIDs; point the scope’s cursor to that row with `last_id=-1`; invoke a matching relay. The admission upsert replaces `-1` with the positive pending intent ID, the adapter executes, and final cursor validation no longer detects the malformed starting state.
- **Impact:** malformed progress metadata is silently rewritten and dispatch proceeds rather than failing explicitly. The existing test misses this because its selected scope contains no dispatchable work. This does **not** establish skipped unresolved work, production authority or duplicate application.
- **Evidence classification:** source-confirmed control-flow defect; this additional scenario was not executed by the assistant or included in the supplied parent results. The candidate claims malformed-cursor failure coverage at `SPEC.md:448–449`.
- **Minimal remediation:** validate the existing cursor before admission can overwrite it, inside the immediate admission transaction. Retain validation for an empty batch.
- **Acceptance proof:** extend the malformed-cursor regression with valid pending scoped work. Expect rejection before adapter invocation, no new dispatch event and unchanged cursor. Demonstrate the intended failure on this candidate, then passing focused/full ordered checks on a new fixed snapshot.
- **Proposed owner:** implementing developer; Ishan reviews disposition.

No Critical or High finding is asserted.
