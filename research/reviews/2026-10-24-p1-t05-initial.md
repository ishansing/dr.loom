## Findings

### R-001 — Ignored kill-denial link insertion can commit a successful but incomplete kill

- **Severity:** Medium.
- **Status:** OPEN.
- **Artifact:** baseline `08292d92fa377c1187d3db21ebe9a5209a124ff4` plus overlay manifest `99f16b0a418491b6e4a0cc90937643257ecd80e2b1dc66f5e770c1ca5d2e103c`.
- **Location:** `src/store.ts:865–866`; engagement completion at `1765–1791`.
- **Confirmed static observation:** after inserting a kill-specific audit denial, `insertActionRow` calls `INSERT INTO kill_denials ... .run(...)` without checking its result or verifying the persisted link. Engagement subsequently validates only the latch before returning success. It does not reread the newly affected action histories.
- **Current requirement:** private durable denial proof and whole-operation failure semantics are explicit at `SPEC.md:350–364,419–422`. SQL ignored-write faults are already part of this candidate’s tested failure model (`tests/kill.test.ts:1081–1097,1179–1196`).
- **Triggering scenario:** create an allowed, never-admitted native action, then install a temporary SQLite fault trigger that ignores insertion into `main.kill_denials`:
  ```sql
  CREATE TEMP TRIGGER ignore_kill_denial
  BEFORE INSERT ON main.kill_denials
  BEGIN
    SELECT RAISE(IGNORE);
  END;
  ```
  Invoke public `engageKill`.
- **Consequence inferred from the inspected path:** the lease revocation, latch, completed control triple and denied audit row can commit without the required link. For an already-allowed action, a later history read rejects the allowed→denied transition because the private exception is absent (`src/store.ts:803–823,893–899`). Reset preparation consequently cannot read that run normally. For a pending request with a linked intent, the missing link also prevents the intended cancelled projection. Engagement nevertheless returns success.
- **Evidence distinction:** the unchecked write and missing postcondition are directly observed. This specific runtime reproduction was **not executed** by this assistant and no parent reproduction result has yet been supplied.
- **Minimal remediation:** require exactly one persisted denial-link insertion, throwing inside the existing immediate transaction if it is ignored. An appropriate `RETURNING` check or checked affected-row result is sufficient; no new abstraction is needed.
- **Acceptance proof:** add a public regression using the fault trigger above and an allowed, never-admitted action, preferably with an intent. Before remediation it should expose the false-success path. After remediation, engagement must throw and preserve the original lease, action, intent and absence of latch/control/denial additions. Retain successful cancellation/link-history tests and rerun ordered gates.
- **Proposed owner:** implementing developer; Ishan reviews the remedy and new artifact.
