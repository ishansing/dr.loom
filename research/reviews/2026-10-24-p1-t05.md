### R-001 — Ignored kill-denial insertion — RESOLVED

- **Original severity:** Medium.
- **Original artifact:** initial T-05 overlay, manifest `99f16b0a418491b6e4a0cc90937643257ecd80e2b1dc66f5e770c1ca5d2e103c`.
- **Original defect:** the private denial-link insertion discarded its result. An ignored insertion could permit engagement to report success while committing an allowed→denied audit transition without its required immutable proof, breaking subsequent action-history/reset reads.
- **Correction:** `src/store.ts:865–870` requires `linked.changes === 1`; failure throws before the enclosing engagement transaction can commit.
- **Acceptance regression:** `tests/kill.test.ts:1198–1233` creates an allowed native action and intent, injects a temporary `RAISE(IGNORE)` trigger on `kill_denials`, and expects engagement to throw. It verifies the original lease/action/intent, no active latch, and zero committed control/denial additions.
- **Red/green provenance:** parent reports that the exact pre-fix command below produced false success instead of the expected throw. Corrected full/focused suites pass. Test setup, checks and correction were directly inspected; execution was not independently reproduced.
- **Owner/remediation status:** implementing developer supplied the minimal remedy and regression. No waiver or further R-001 correction is requested.

### Adjacent legacy-latch question — REPRODUCED AND RESOLVED

The initial report explicitly recorded this as a question, not a separately confirmed finding. That history is preserved.

- **Original concern:** ignored legacy-latch adoption could leave a non-null legacy latch while engagement reported a completed native operation.
- **Subsequent evidence:** parent reproduced false success before correction using the public engagement API.
- **Correction:** `src/store.ts:1762–1767` requires exactly one latch write; `1787–1789` additionally requires the persisted latch’s `eventId` to equal the issued completed event ID.
- **Regression:** `tests/kill.test.ts:1235–1262` covers both an ignored legacy-latch update and an after-update fault that drops the event reference. Both must throw, preserve the prior legacy latch/lease/action and leave no committed new control rows.
- **Impact review:** ordinary legacy adoption still preserves prior latch evidence (`tests/kill.test.ts:606–645`). New checks remain inside the existing immediate transaction, add no authorization path and do not reset or re-grant anything.
- **Disposition:** resolved on this candidate; not silently omitted or retroactively represented as an initial confirmed finding.
