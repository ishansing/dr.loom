## Findings

### R-001 — High: Literal `*` in a target can bypass a wildcard deny

- **Artifact/file:** `T06-20261024-01`, `C/src/policy.ts:103–113`; deny selection at `:156–161`.
- **Confirmed observation:** `matchPattern` checks literal character equality before handling the `*` wildcard. When both current characters are `*`, it consumes the pattern star without recording a wildcard/backtracking position.
- **Concrete case:** `matchPattern("docs/*", "docs/*secret")` follows the literal-equality branch at line 104, then returns false after the pattern ends. Conversely, the broad pattern `"*"` matches `"docs/*secret"`.
- **Impact/trigger:** With a global deny for `docs/*` and a global allow for `*`, the valid workspace-relative filename `docs/*secret` misses the deny and matches the allow. With otherwise valid admission state, `authorize` can return allow. This violates deny-wins within the current synthetic contract; no real effect execution was demonstrated.
- **Minimal remediation:** Recognize a pattern `*` as a wildcard before the literal-equality branch, preserving correct retry/backtracking behavior.
- **Acceptance proof:** Add public regressions for `matchPattern("*", "*x") === true`, `matchPattern("docs/*", "docs/*secret") === true`, and `evaluatePolicy`/`authorize` denying `docs/*secret` under deny `docs/*` plus allow `*`. Include repeated-star and trailing-suffix near misses to protect anchoring.
- **Proposed owner:** T-06 policy implementation owner.
- **Verification status:** Confirmed by static control-flow inspection; reproduction not executed by this assistant.

### R-002 — Medium: Database secret classification omits SQLite sidecars

- **Artifact/file:** `T06-20261024-01`, `C/src/policy.ts:82–83,184–188`; gate at `C/src/store.ts:1588–1590`.
- **Requirement:** `C/SPEC.md:394–396` requires denial of key/DB-like secret targets.
- **Confirmed observation:** Database suffixes are anchored to the end of the path: `sqlite|sqlite3|db)$`. Therefore `db/loom.sqlite-wal`, `db/loom.sqlite3-wal` and `db/loom.db-journal` are not classified secret-adjacent.
- **Impact/trigger:** A permissive read policy can admit these workspace-local targets with otherwise valid state. SQLite WAL/journal sidecars can contain database content, so blocking the database filename alone leaves a lexical hole in the stated DB-like secret guard.
- **Minimal remediation:** Extend database-file classification to the relevant SQLite companion suffixes, without claiming that suffix matching establishes production containment.
- **Acceptance proof:** Add classifier and public `authorize` tests denying database files and their `-wal`, `-shm` and `-journal` companions under an allow rule. Keep unrelated ordinary filenames as negative controls.
- **Proposed owner:** T-06 policy implementation owner.
- **Verification status:** Confirmed lexical classification gap by inspection; no real database content accessed or exposure demonstrated.

### R-003 — Medium: Exhausted tool-call budget is evaluated after lease rejection

- **Artifact/file:** `T06-20261024-01`, `C/src/store.ts:1643–1668`.
- **Requirement:** `C/decisions.md:837–839` specifies policy/risk/**budget check → lease → budget draw**; `C/SPEC.md:289–291` likewise places budget evaluation before lease.
- **Confirmed observation:** Cost caps are checked before lease, but the tool-call cap is checked only inside `drawBudget`, after `checkLease`. A lease denial skips that draw and its budget-breach audit entirely.
- **Impact/trigger:** An otherwise allowable request with `tool-calls.limit = 0` and a stale/missing lease reports `lease`, rather than the earlier budget rejection, and emits no tool-call breach evidence. Admission still fails closed; this is an ordering and audit-contract defect, not an overdraw.
- **Minimal remediation:** Read/validate the tool-call budget and check the prospective one-call draw before lease validation in the same immediate transaction. Only consume the draw after lease success.
- **Acceptance proof:** Add a public `authorize` regression combining an exhausted call cap with an invalid lease. Assert budget reason, attributable breach audit and unchanged usage. Also assert that a valid, unexhausted budget is not consumed when lease validation fails.
- **Proposed owner:** T-06 store/gate implementation owner.
- **Verification status:** Confirmed by static branch ordering; new regression not executed.
