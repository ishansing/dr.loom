# R-29 Pi adapter pre-implementation review — 2026-10-19

- **Trigger:** requested verification of Pi 1.3.0 adapter APIs and execution
  hook coverage before deciding whether Loom needs a fork.
- **Baseline:** historical Pi research at npm `0.99.2`; no installed Pi
  dependency in Loom and no version promotion in this change.
- **Checked release:** official `v1.3.0` tag,
  `71023aec1546d6d677a65669c5665c0927ce0dd0`, and published
  `@earendil-works/pi-coding-agent@1.3.0` with registry SHA-512 verified.
  Exact sources, API matrix and runtime proof:
  [API review](../pi/10-pi-1.3.0-api-review.md).
- **Contract differences:** custom-start `before_agent_start` union,
  retained MCP tools under ordinary allowlists, dedicated usage/cache-warm
  accounting, removed source-only experimental stack. System One validation
  gaps remain; the offline catalogue lacks versioned Jev IDs and has zero
  input pricing.
- **Execution finding:** hooks are not universal effect interception.
  See [coverage, counterexamples and no-fork conditions](../pi/11-pi-1.3.0-execution-coverage.md).
- **Decision (adopted 2026-10-20):** upstream Pi, no fork; external Loom
  authority plus isolated whole-Pi execution, owned final-input/output and
  completion gates, explicit channels and honest cancellation/reconciliation.
  See [SPEC](../../SPEC.md#runtime-architecture-and-security-boundary-2026-10-20-decision)
  and [research decision record](../pi/11-pi-1.3.0-execution-coverage.md#6-adopted-loom-design-decisions-2026-10-20).
  T-15 is now required before untrusted adapter execution. This is not
  production conformance proof and does not promote `1.3.0`.
- **Verification:** published SDK/classifier offline assertions passed on
  Node `26.7.0` and Bun `1.4.3`; execution probes and source evidence are
  detailed in the companion coverage note. No real provider traffic.
- **Next action:** at T-08–T-11, select the version explicitly, convert the
  findings into adapter conformance tests, and prove sandbox/process-tree,
  mandatory-hook, completion and kill/effect-boundary behavior before
  granting production authority. I2P/MCP/provider releases were not rechecked.
