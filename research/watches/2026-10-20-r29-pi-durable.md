# R-29 — Pi Durable assessment, 2026-10-20

- **Trigger:** user requested assessment of Pi Durable as a Loom dependency.
- **Existing baseline:** historical Durable `0.99.2` research; dependency
  deferred in SPEC. No installed Pi/Durable runtime dependency in Loom.
- **Checked sources:** official launch post; npm `1.3.0` metadata/tarball
  (SHA-512 verified); release source
  `71023aec1546d6d677a65669c5665c0927ce0dd0`; current main snapshot
  `fdce48eb404ec014adaf2ac10a3a53bc6b1740c2`.
- **Material findings:** separate experimental harness, not a coding-agent
  plugin; useful durable conversations/tasks/documents and nested call
  machinery. Current main has unreleased durable sleeps/crash-loop/telemetry
  and document API changes, plus a SQLite schema upgrade incompatible with
  rollback to 1.3.0. Runtime persistence does not replace Loom authority,
  effect-side idempotency, isolation or independent verification.
  Safe tool recovery skips pre-tool hook/schema checks; dispatch-time live
  authorization remains mandatory. Same-type `requestId` payload collisions
  return the original submission; background work survives ordinary abort.
- **Evidence:** [adoption/API assessment](../pi/12-pi-durable-adoption.md)
  and [recovery/boundary investigation](../pi/13-pi-durable-recovery-boundaries.md)
  distinguish inspected contracts, offline probes and remaining proof.
- **Decision:** investigate as an alternative isolated runner before T-08
  freezes; no adoption or runtime/framework/model pin change. Keep the
  current SPEC authority/isolation decisions and dependency deferral.
- **Verification:** published-package API assertions passed on Node `26.7.0`
  and Bun `1.4.3` for memory/SQLite/JSONL, including clean reopen for persistent
  backends. These are not crash/power-loss, real-provider or sandbox proofs.
  Nine recovery/boundary assertions against published 1.3.0 also passed on
  parent rerun; see the companion note for their temporary script and limits.
- **Next action:** explicit authorization for a contained comparative pilot,
  then a reviewed runtime/adapter/state-ownership decision with conformance
  and rollback evidence. I2P, MCP releases and model quality were not rechecked.
